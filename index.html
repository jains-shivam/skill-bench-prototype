Skill Bench prototype compare versions
Built on Harbor + Daytona

Three click-through versions for the team review

V1 is the first prototype. V2 reworks it as a relay (Prompter -> Tester -> Reviewer) with skills + Harbor preview. V3 layers on Projects / Batches / Delivery, a Project Manager role, a co-authored task.toml, a Tester solution editor, expanded environment config, and a Skills Lifecycle Manager.

One Trainer persona owns the whole task: instruction, environment, criteria, solution, Oracle. 7 wizard steps. No skills, no Harbor folder preview, no with/without-skills evaluation.

What changed across V1 -> V2 -> V3

Each row maps to one feedback point. V3 builds on V2, so most V2 rows still apply.

Topic V1 V2 V3
Top-level scope Flat list of tasks. No project / batch concept. Flat list of tasks. No project / batch concept. Project → Batch → Delivery Batch with a workspace switcher in the top nav. Dashboards are scoped to the current batch via breadcrumbs.
Project Manager role Trainer wears every hat. Prompter / Tester / Reviewer / Evaluator / Admin. New Project Manager persona who creates projects + batches, assigns prompters and testers, and ships delivery batches.
task.toml authoring Generated from a single wizard, no explicit editor. Generated from Prompter's Brief step; not directly edited. Co-authored: Prompter writes the identity fields, Tester writes the execution fields (image, resources, timeouts, network, env vars). Structured editor + raw TOML tab. Marked shared in the Harbor preview.
Tester environment config Limited to packages list. Visual builder / upload / raw Dockerfile editor. Same tabs plus base image, language preset, CPU / memory / disk / GPU, timeouts, network mode, env vars (secret-aware). Daytona safety banner spells out the sandbox model.
Solution editing by Tester Trainer owns the solution; no separate cleanup phase. Tester sees the solution as read-only. New Solution review Tester step with a GitHub-style file tree + editor, AI tidy action, and a diff toggle vs. the Prompter's original (preserved at solution/_original/).
Skills lifecycle No skills. Library of skills, no state model. Admin Skills Lifecycle Manager with Draft / Published / Deprecated / Archived states, version history, usage stats, and lifecycle actions.
Allow submit after prompt + golden solution Trainer has to also build environment, criteria, and pass Oracle before they can submit anything. Prompter wizard ends after Solution; submission unblocks the next role. Same as V2.
Full preview in draft / review mode Tabbed summary, no folder view. Harbor preview panel (folder tree + file viewer) everywhere. Same panel, with shared-owner handling and Tester-side Edit affordance for solution files.
Separate multi-step forms for Tester and Prompter One Trainer role with a single 7-step form. Prompter (6 steps) and Tester (4 steps). Prompter (6 steps) and Tester (5 steps) - new Solution review step.
Allow Prompter to add skills No skills. Skills wizard step; skills compile into environment/skills/<id>/SKILL.md. Same flow, now pulling from the admin-managed skill registry with lifecycle state.
Evaluator: run with / without skills Evaluator picks agents only. Required Skill mode radio: With / Without / Both (A/B). Same as V2.
File ownership during testing Single Trainer authors everything. Tester authors Dockerfile + test.sh + rewardkit.yaml; Prompter retains instruction / skills / solution. Same V2 ownership, plus task.toml shared and solution/ now Tester-editable for tidy-up.
Suggested V3 demo order
  1. Open V3 as Project Manager - see Projects, batches, delivery pipeline, and recent activity.
  2. Click into Acme Coding / Sprint 3 to see batch-scoped tasks + KPI strip.
  3. Switch to Prompter - dashboard is breadcrumbed to the same batch.
  4. Switch to Tester, open Environment: Daytona banner, expanded env, new task.toml co-author editor.
  5. Continue to Solution (new step): file tree + AI tidy + diff vs. prompter's original.
  6. Switch to Admin - Skills tab: lifecycle states, version history, deprecate / archive actions.
  7. Open a Delivery Batch from any project - shows frozen manifest of approved tasks.
